# Voiceover with Kokoro

Full reference: **`docs/voice.md`**. Everything runs locally through the CLI;
never hand-manage audio files.

## Everyday flow

```bash
node tools/video.mjs tts <name> --play      # synth + concat + sync + play
node tools/video.mjs play <name>            # full track
node tools/video.mjs play <name> --line L3  # single line audition
```

## The edit loops

| Request | Command |
|---|---|
| Fix line 3's wording | edit `script.json` → `video tts <name> --only L3 --play` |
| Try a different voice | `video tts <name> --voice am_michael --only L1 --play` → `--force` once chosen |
| Faster/slower | `--speed 1.1` (0.8–1.3 range) |
| Regenerate everything | `--force` |

Only changed lines re-synthesize (content-hashed cache) — re-runs are cheap.

## Voice selection protocol

1. Don't switch voices speculatively — offer 2–3 candidates.
2. Audition each on the SAME line (`--only L1`), ask the human to compare.
3. Once chosen: `--force` to render the whole track with it, re-play in full.

## Approval discipline

- Play the FULL track after any change — a changed line shifts every
  `startFrame` after it.
- `audioApproved: true` in `project.json` only on explicit human confirmation.
- Any later text/voice change flips approval back to `false`.

## Never do this

- Don't `<Audio>` anything inside scenes — `Video.tsx` plays `voiceover.wav`.
- Don't hand-edit `audio/manifest.json` or `video/src/data/timeline.ts`
  (regenerated by `video sync`, which `tts` runs for you).
- Don't edit the generated `project.json` audio fields manually beyond the
  approval flags.

## Troubleshooting

See "Troubleshooting" in `docs/voice.md`. `video doctor` validates uv, models
and players in one shot.
